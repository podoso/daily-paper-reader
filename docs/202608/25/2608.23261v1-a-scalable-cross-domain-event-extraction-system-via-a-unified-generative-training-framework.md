## 摘要
事件抽取是信息抽取的基础。以往的方法通常将事件检测和论元抽取分开处理，或者依赖于特定数据集的设计，限制了可扩展性和跨领域泛化能力。我们提出了一种统一的生成式序列到序列框架，该框架联合执行事件抽取子任务，并支持流水线和端到端两种配置。我们在多个不同领域的事件数据集上对预训练语言模型进行微调，使单一模型能够保留领域特定语义，同时在较大且不断演化的标签空间上实现泛化。我们通过一个面向研究人员和从业者的基于Web的应用来展示这些能力。该平台支持文档上传、基于模式的事件抽取、触发词和论元的可视化，以及跨领域不同抽取配置的比较。

## Abstract
Event extraction is fundamental to information extraction. Prior approaches often separate event detection and argument extraction or depend on dataset-specific designs, limiting scalability and cross-domain generalization. We propose a unified generative sequence-to-sequence framework that performs event extraction subtasks jointly and supports both pipeline and end-to-end configurations. We fine-tune pretrained language models on multiple event datasets across diverse domains, enabling a single model to retain domain-specific semantics while generalizing over large and evolving label spaces. We demonstrate these capabilities through a web-based application tailored for researchers and practitioners. The platform supports document upload, schema-aware event extraction, visualization of triggers and arguments, and comparison of different extraction configurations across domains.

  - 将事件检测（ED）与事件参数抽取（EAE）分离为独立子任务，采用流水线架构，导致错误传播和工程复杂度高。

- **核心动机**：需要一个统一的、可扩展的跨域事件抽取系统，能够在不需大量重新设计的前提下，适应不同领域、数据集和大型动态标签空间。

## 二、方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想
- 将事件抽取统一表述为序列到序列（sequence-to-sequence）的生成任务，由单一模型同时处理触发词识别、事件类型分类和参数抽取。
- 通过任务标识符和领域标识符的条件化设计，使模型能够在多个数据集上联合训练，保留领域特定语义的同时实现跨域泛化。

### 2.2 关键输入格式
- **统一输入格式**：`{dataset name} + {task prefix} + {text}`
  - `dataset name` 作为领域指示器和模式指南（schema guide）。
  - `task prefix` 定义具体子任务（如事件检测或参数抽取）。
- 在推理时，只需指定对应领域名称即可引导模型预测到相关域，适应大型且演化的标签空间。

### 2.3 两种推理模式
- **流水线模式（Pipeline）**：
  - 第一步：检测输入文本中的事件触发词。
  - 第二步：基于所选数据集模式，对检测到的触发词进行事件类型分类。
  - 第三步：根据预测的事件类型及其关联的论元角色，执行参数抽取。
  - 优点：各阶段显式可控，支持可解释性和分阶段评估。
- **端到端模式（E2E）**：
  - 将触发词识别和事件类型分类合并为单次预测，简化推理并减少错误传播。
  - 完全端到端（即包含参数抽取）也可实现，但由于输出空间复杂度更高，更具挑战性。
- 两种模式通过各自对应的输入和目标模式切换，无需修改核心架构。

### 2.4 模型基础
- 基于 T5 架构（约 2.2 亿参数的 T5-base）进行微调。
- 框架允许使用单一模型统一处理事件检测和参数抽取，减少多个独立模型的维护成本。

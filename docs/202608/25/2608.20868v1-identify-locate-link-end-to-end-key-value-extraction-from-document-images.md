## 摘要
文档处理流程传统上将光学字符识别（OCR）引擎与下游的结构化信息提取模型级联，导致多阶段错误传播。我们对SmolDocling——一个紧凑的2.56亿参数视觉语言模型（VLM）——进行微调，使其能够直接从文档图像中执行端到端的键值提取，无需OCR预处理即可在单次传递中联合解决识别、定位和关联问题。我们扩展了DocTags，增加了专门的键、值、区域和链接标签，从而在统一的输出序列中支持多对多关系。为应对数据局限性，我们设计了一种增强流水线，结合了合成表单填充和基于图的裁剪，以保留完整的键值子图。我们进一步引入了一个布局感知的评估框架，将文本匹配与空间边界框验证相结合。在FUNSD、XFUND和大型私有数据集上，我们的模型在布局感知评估中优于更大的零样本VLM基线，同时比Qwen2.5-VL（7B）小27倍，推理速度快5倍以上。模型权重将在发表后公开发布。

## Abstract
Document processing pipelines traditionally cascade optical character recognition (OCR) engines with downstream models for structured information extraction, leading to multi-stage error propagation. We fine-tune SmolDocling, a compact 256M-parameter vision-language model (VLM), to perform end-to-end key-value extraction directly from document images, jointly solving identification, localization, and association in a single pass without OCR preprocessing. We extend DocTags with specialized key, value, region, and link tags, enabling many-to-many relationships in a unified output sequence. To address data limitations, we design an augmentation pipeline combining synthetic form filling and graph-based crops that preserve complete key-value subgraphs. We further introduce a layout-aware evaluation framework extending text matching with spatial bounding box verification. On FUNSD, XFUND, and a large-scale private dataset, our model outperforms larger zero-shot VLM baselines under layout-aware evaluation, while being 27 times smaller than Qwen2.5-VL (7B) and over 5 times faster at inference. The model weights will be released publicly after publication.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **背景**：企业超过 80% 的信息存储于非结构化文档中（发票、合同、医疗表格、监管文件等），而结构化知识提取是主要瓶颈。
- **核心问题**：传统文档键值提取流程将 OCR 与下游模型级联（如 LayoutLMv3、LayoutXLM 等多模态编码器），形成多阶段流水线，存在以下弊端：
  - **错误传播**：OCR 识别错误会向下游传递且无法恢复；
  - **语言依赖**：OCR 支持的语言范围限制了系统的通用性；
  - **工程复杂**：多组件协调困难，输出碎片化需要后处理。
- **任务定义**：键值提取包含三个相互关联的子任务：
  1. **识别（Identification）**：区分文本元素是键（Key）还是值（Value）；
  2. **定位（Localization）**：预测每个元素的边界框；
  3. **关联（Association）**：建立键与值之间的有向关系，支持多对多映射，构成有向图结构。
- **论文主张**：一个紧凑的 256M 参数视觉语言模型，通过任务特化微调，可以在**单次前向传播**中端到端完成全部三个子任务，无需外部 OCR 或布局分析，且性能优于更大的零样本 VLM 基线。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 问题形式化
- 给定文档图像 I ∈ R^{H×W×3}，提取目标为：
  - **F : I → { (kⱼ, vₖ, Bⱼ, Bₖ) : (kⱼ, vₖ) ∈ R }**
  - 其中 B 为边界框，R 支持多对多链接，构成有向图 **G = (K ∪ V, R)**。

### 2.2 DocTags 扩展（统一输出表示）
- 基于 SmolDocling 的 DocTags 格式，新增四种专用标签：
  - `<key_value_region>`：封装包含相关键值对的区域；
  - `<key_i>`：带唯一标识符 i 的键元素；
  - `<value_j>`：带唯一标识符 j 的值元素；
  - `<link_k>`：建立从当前元素到标识符 k 的定向链接。
- 每个元素通过 4 个连续的位置 token（`<loc_x1><loc_y1><loc_x2><loc_y2>`）编码边界框，坐标归一化至 [0, 500]。
- 默认采用 **link-in-key** 策略（链接锚定在键中，在解码目标值之前生成链接）；消融实验还探索了 link-in-value 策略及按左上角坐标的空间排序序列化。

### 2.3 模型架构
- 基于 SmolDocling（256M 参数），包含两个组件：
  - **视觉编码器**：SigLIP，patch size 16，93M 参数，将图像编码为 patch embeddings，经线性投影和 pixel-shuffle pooling（序列长度缩减 4 倍）后输入解码器；
  - **语言解码器**：SmolLM2（135M 参数），自回归生成 DocTags token 序列。
- 词表扩展了键值标签、位置 token 和链接标识符的特殊 token。
- 微调时**所有参数（编码器、投影器、解码器）均不冻结**。

### 2.4 训练目标
- 标准交叉熵损失，条件于视觉 token。
- 探索了 **token 加权损失**变体：对结构 token（如 `<key_value_region>`、`<key>`、`<value>`、`<link>`）赋予权重 λ=5，防止高频内容 token 主导损失。

### 2.5 数据增强流水线
1. **合成表单填充**：针对 DocLayNetV2 中大量空白表单字段，使用 Qwen2.5-VL 72B 生成上下文合适的值，并通过自适应字体大小和多行换行渲染到空白区域，同步更新边界框标注；
2. **基于图的裁剪增强**：构建键值链接图 → 计算连通分量并合并空间邻近分量 → 添加随机填充生成裁剪样本，保留完整键值子图；
3. **图像变换**：腐蚀/膨胀（借鉴 Nougat）、高斯噪声、高斯模糊、颜色抖动、位图阈值化、JPEG 压缩伪影（Albumentations 实现），所有变换保持边界框有效性。

### 2.6 布局感知评估框架
- 实体成为真正例需同时满足三个条件：
  1. 文本匹配（Levenshtein 相似度 ρLev ≥ 0.8）；
  2. 语义标签一致（key/value）；
  3. 空间重叠 IoU ≥ 0.7。
- 使用**匈牙利算法**进行全局最优二分匹配（解决同一文本出现在多个位置时的分配问题）。
- 对预测边界框的模型（本文模型、Qwen2.5-VL）使用布局感知评估；对无空间信息的模型（GPT-4o、Llama-3.2）使用纯文本评估。

## 6. 主要结论与发现

1. **紧凑模型可胜任端到端键值提取**：256M 模型在布局感知评估下全面超越 7B 的 Qwen2.5-VL（FUNSD SER 0.514 vs 0.273，RE 0.275 vs 0.144；XFUND SER 0.412 vs 0.285，RE 0.206 vs 0.123；DocLayNetV2 SER 0.485 vs 0.179，RE 0.321 vs 0.074），体积小 27 倍、推理快 5 倍以上。
2. **任务特化微调 + 良好数据流水线比模型规模更重要**：在无 OCR 设置下，小模型的定向微调优于大模型的零样本泛化。
3. **数据流水线组件贡献不均**：
   - 裁剪增强带来最大增益（XFUND RE 提升 ~41%，0.122 → 0.172）；
   - 合成表单填充持续提升 FUNSD 和 XFUND 性能；
   - 图像变换对噪声扫描文档（FUNSD）有益，但对干净 PDF（DocLayNetV2）略有损害；
   - 空间排序和链接放置策略在 SER 和 RE 之间存在权衡，无单一配置全面占优。
4. **模型仍不及基于 OCR 文本/布局的编码器模型**（如 LayoutXLM large），但该比较本质上不对称。

## 7. 优点

- **端到端设计**：真正免除 OCR 依赖，单次前向传播联合解决识别、定位、关联，消除错误传播；
- **统一输出格式**：DocTags 扩展以单一结构化序列支持复杂多对多关系，无需任务特化后处理；
- **紧凑高效**：256M 参数适合端到端/设备端部署，推理速度快；
- **数据增强创新**：合成表单填充（利用大模型生成语义合理值）和基于图的裁剪（保留完整键值子图）有效缓解训练数据稀缺；
- **布局感知评估框架**：将空间 IoU 验证引入指标，比纯文本匹配更贴合真实应用，且用匈牙利算法解决全局分配；
- **多语言验证**：XFUND 7 语言覆盖验证了跨语言泛化能力。

## 8. 不足与局限

- **与最强基线存在差距**：仍不及接收预提取文本/框的 OCR 编码器模型（如 LayoutXLM large），在需要极致精度的场景中可能不是最优选择；
- **数据限制**：公开的带空间键值标注的数据集极少（仅 FUNSD/XFUND），限制训练多样性和评估覆盖；DocLayNetV2 为私有数据，无法独立验证；
- **阅读顺序缺失**：现有数据集缺乏阅读顺序信息，迫使使用基于坐标的序列化，对多栏复杂布局（坐标序 ≠ 逻辑阅读序）效果不佳；
- **已知错误模式**：OCR 识别错误、空间远距离/重复字段的链接遗漏、多词实体的边界分割误差、深度嵌套的多对多关系仍是挑战；
- **评估公平性偏差**：VLM 基线为零样本，未经验证其微调后是否仍落后；纯文本评估与布局感知评估并存导致跨模型比较口径不完全统一；
- **训练细节未完全披露**：如 DocLayNetV2 的具体过滤标准、合成填充的质量控制等描述有限，可复现性有待提升。

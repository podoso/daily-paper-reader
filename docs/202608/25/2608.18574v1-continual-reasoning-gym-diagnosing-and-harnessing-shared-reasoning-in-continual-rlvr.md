## 摘要
带可验证奖励的强化学习（RLVR）通常会在多个任务上对推理模型进行后训练，而随着新任务的加入，重新运行多任务RLVR（MTRL）会使能力扩展成本高昂。因此，我们研究持续RLVR，即随着每个任务的到来更新现有模型。核心问题是：以这种方式更新的模型能否表现得与联合训练的模型一样好？为了回答这个问题，我们引入了持续推理健身房（Continual Reasoning Gym），这是一个持续RLVR环境，将文本和视觉推理任务组织成五个任务序列。在此设置中，我们发现了两个关键观察：顺序RLVR表现出适度的遗忘，但其最终性能仍低于MTRL。为了理解后者，我们分解了最终性能，并表明遗忘仅解释了部分差距。为了解释前者，我们识别出共享推理：可迁移的推理结构使得对某一任务的训练平均能够支持其他任务。因此，我们引入了持续提示重放（CPR），它通过重放先前任务的提示并用当前策略重新生成其响应，利用共享推理来改善对到达和未来任务的学习。平均而言，只有CPR达到了MTRL级别的性能。

## Abstract
Reinforcement learning with verifiable rewards (RLVR) commonly post-trains reasoning models on multiple tasks, while rerunning multitask RLVR (MTRL) as new tasks are added makes capability expansion costly. We therefore study continual RLVR, which updates the existing model as each task arrives. The central question is whether a model updated this way can perform as well as a jointly trained model. To answer this question, we introduce Continual Reasoning Gym, a continual-RLVR environment that organizes text and visual reasoning tasks into five task sequences. In this setting, we identify two key observations: Sequential RLVR exhibits modest forgetting, yet its final performance remains below that of MTRL. To understand the latter, we decompose final performance and show that forgetting accounts for only part of the gap. To explain the former, we identify shared reasoning: transferable reasoning structure allows training on one task to support others on average. We therefore introduce Continual Prompt Replay (CPR), which harnesses shared reasoning to improve learning on the arriving and future tasks by replaying previous-task prompts and regenerating their responses with the current policy. On average, only CPR reaches MTRL-level performance.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：带可验证奖励的强化学习（RLVR）通常通过多任务联合训练（MTRL）对推理模型进行后训练。但实际部署中会不断出现新任务（如新 API、用户偏好变化），若每次新任务到来都重新在扩大的任务混合集上跑多任务 RLVR，计算成本过高。
- **研究问题**：持续 RLVR（Continual RLVR）——按任务到达顺序逐步更新已有模型——能否达到与联合训练（MTRL）相当的性能？
- **核心发现**：
  - 顺序 RLVR（Seq. RLVR）确实只表现出“适度遗忘”，但其最终性能平均仅达到 MTRL 的 88%，仍存在差距。
  - 遗忘只解释了 MTRL 差距的一部分；性能差距还来自对到达任务的学习效果（TLG）和前期任务对后续任务的帮助（FWT）。
  - 识别出“共享推理”（shared reasoning）：任务间存在可迁移的推理结构，使某一任务上的训练平均上有助于其他任务，这解释了适度遗忘现象。
  - 提出 **持续提示重放（Continual Prompt Replay, CPR）**，通过回放先前任务提示并用当前策略重新生成响应来利用共享推理，是唯一在平均性能上达到 MTRL 级别的持续学习方法。

## 2. 方法论

### 2.1 持续 RLVR 形式化

- 将每个任务建模为 token 级 MDP：状态为提示条件化的 token 前缀，动作空间为词表，奖励由程序化验证器给出（终止时返回 0/1）。
- RLVR 目标：\( J_i(\theta) = E_{x\sim D_i, y\sim\pi_\theta(\cdot|x)}[r_i(x,y)] \)。
- 持续学习协议：从基础策略 \( M_0 \) 出发，按阶段依次在任务 \( \tau_1,\dots,\tau_T \) 上训练，得到 \( M_1,\dots,M_T \)，最终评估所有任务的平均成功率。

### 2.2 CRG 基准（Continual Reasoning Gym）

- 将静态任务池转换为分阶段、非平稳的训练流，共 **5 条任务序列、30 个阶段**：
  - **LLM 算法推理**（10 个任务）：进制转换、二进制交替、二进制矩阵、凯撒密码、字母算术、同构字符串、水壶问题、矩阵旋转、字符串操作、A::B 重写。
  - **LLM 代数推理**（6 个任务）：复数运算、中等积分、多项式方程、多项式乘法、简单方程、简单积分。
  - **VLM 定量推理**（4 个任务）：线性数量、素数数量、点数量、计数数量。
  - **VLM 空间推理**（6 个任务）：组装、截面、六面体、三视图、空间顺序、多面体旋转。
  - **VLM 位置推理**（4 个任务）：平移、旋转、比较、翻转。
- 答案均为程序化验证器可判定的符号答案或多选答案。

### 2.3 评价指标

- **BaseAvg / FinalAvg**：训练前/全部训练后的平均成功率。
- **FWT（前向迁移）**：任务自身训练之前，前期训练带来的收益。
- **TLG（任务学习增益）**：直接在该任务上训练带来的收益（本文新增）。
- **BWT（后向迁移/遗忘）**：后续训练对前期任务的收益或损害。
- **CTM（持续与多任务比）**：\( \text{CTM} = \frac{\text{FinalAvg}}{\text{FinalAvg}_{\text{MTRL}}} \)，CTM=1 表示达到 MTRL 水平。

### 2.4 关键理论分解

**命题 1（超越遗忘的最终性能分解）**：

\[
\text{FinalAvg} = \text{BaseAvg} + \frac{T-1}{T}\text{FWT} + \text{TLG} + \frac{T-1}{T}\text{BWT}
\]

- 该式将最终性能分解为基线、前向迁移、直接任务学习和后向迁移四项。
- 由于同一任务序列内所有方法共享相同初始策略，因此 \( \Delta\text{BaseAvg}=0 \)，任何方法与 MTRL 的差距都可以归因于 FWT、TLG、BWT 三项。

### 2.5 共享推理（Shared Reasoning）

- **假设 1（均值任务梯度对齐）**：对推理任务，期望 \( E_{t,i,k}[\langle g_i^{(t)}, g_k^{(t)}\rangle] \ge 0 \)，即任务间梯度平均对齐。
- **推论 1**：在均值对齐假设下，后续阶段更新对前期任务目标的一阶贡献期望非负，从而解释了“适度遗忘”。

### 2.6 CPR 方法细节

- **核心思想**：在后续阶段训练中，从已存储的先前任务提示池中选出“处于中等掌握水平”的提示，替换当前 batch 中的部分当前任务提示，然后用**当前策略**重新生成响应，并由各自任务验证器打分后参与 GRPO 更新。
- **更新方向**：
  \[
  g^{\text{CPR}}_t = (1-\hat\rho_t)g_t^{(t)} + \hat\rho_t\sum_{k<t} q_{t,k}g_t^{(k)}
  \]
  其中 \( \hat\rho_t \) 为重放提示比例，\( q_{t,k} \) 为重放提示中来自任务 \( k \) 的比例。
- **提示选择策略**：只选择最新通过率落在 [0.24, 0.70] 区间的先前任务提示；优先选择通过率最接近 0.5 的提示；每条提示重放后有 5 次更新的冷却期。
- **关键特点**：
  - 不增加每个 update 的 rollouts 数量（每个提示仍生成 5 条响应），只改变任务采样分布。
  - 存储开销极小：平均每条提示序列化后仅 1.24 KiB。
  - 与“旧轨迹重放”的本质区别在于：CPR 用当前策略重新生成响应，而不是复用旧策略的轨迹。

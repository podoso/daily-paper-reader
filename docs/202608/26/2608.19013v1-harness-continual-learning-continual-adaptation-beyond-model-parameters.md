## 摘要
持续学习在很大程度上以模型为中心，将模型参数视为随顺序经验变化的状态。现代智能体还可以通过由提示、记忆、工具、技能和路由规则组成的工具集进行适应。由于这些内容共同塑造后续执行，工具集更新即使模型被冻结也可能破坏先前可靠的行为。这提出了一个新问题：智能体如何在不改变模型的情况下，持续改进其模型外部的状态，同时保留早先获得的行为？我们提出了工具集持续学习（HCL），一种新的持续学习范式，其中工具集围绕冻结的基础模型进化，并将由此产生的早期行为丧失定义为工具集级遗忘。我们用四个面向执行的组件实例化HCL：任务接口、经验记忆、能力图谱和自适应路由器。我们进一步引入受保护的工具集进化，将更新生成与状态提交分离。持续优化器根据执行后反馈提出候选工具集，持续评估器仅在检查当前改进、历史保留和有效性之后才提交生成的候选工具集。在文本推理、多模态感知和开放世界交互上的实验展示了能力积累和故障恢复，在多种设置下相对基线取得了超过10%的增益。组件消融评估了每个工具集组件的贡献，而受控的保留扫描揭示了可测量的工具集级遗忘，并表明稳定性-可塑性权衡可以被显式调整。

## Abstract
Continual learning has largely been model-centric, treating model parameters as the state that changes with sequential experience. Modern agents can also adapt through a harness of prompts, memories, tools, skills, and routing rules. Because these contents jointly shape later execution, a harness update can disrupt previously reliable behavior even when the model is frozen. This raises a new question: how can an agent continually improve its state outside the model while retaining behavior acquired earlier? We formulate Harness Continual Learning (HCL), a new continual learning paradigm in which the harness evolves around a frozen foundation model, and define the resulting loss of earlier behavior as harness-level forgetting. We instantiate HCL with four execution-facing components: the Task Interface, Experience Memory, Capability Map, and Adaptive Router. We further introduce guarded harness evolution to separate update generation from state commitment. A Continual Optimizer proposes candidate harnesses from post-execution feedback, and a Continual Evaluator commits the resulting candidate harness only after checking current improvement, historical retention, and validity. Experiments on textual reasoning, multimodal perception, and open-world interaction demonstrate capability accumulation and failure recovery, with relative gains exceeding 10% over corresponding baselines in multiple settings. Component ablations assess the contribution of each harness component, while controlled retention sweeps reveal measurable harness-level forgetting and show that the stability--plasticity trade-off can be explicitly adjusted.

## 2. 论文提出的方法论

### 2.1 核心思想

- 将装置视为一个统一的、持续演化的学习状态，更新对象是围绕冻结基础模型的四个执行组件；
- 采用**受保护的装置演化（guarded harness evolution）**，将候选生成与状态提交分离：先由优化器生成候选，再由评估器通过三重检查决定是否提交；
- 历史保留成为装置更新的**显式条件**，而非隐含假设。

### 2.2 装置状态的四组件结构

论文将装置状态定义为 Hn = (In, Mn, Cn, Rn)，四个组件联合版本化：

| 组件 | 执行功能 | 可更新内容 |
|------|----------|------------|
| **Task Interface (In)** | 将原始交互（指令、观察、多模态输入）转换为结构化表示 in = (xn, gn, kn)，即输入、目标和约束 | 提示词、任务模板、解析与规范化规则 |
| **Experience Memory (Mn)** | 提供具体交互记录和可复用的抽象指导 | Raw Memory（原始交互记录）+ Abstract Memory（LLM 摘要生成的复用性指导） |
| **Capability Map (Cn)** | 提供外部操作和可复用的内部技能 | 外部能力（API、检索、感知模型等）+ 从 Abstract Memory 中提炼的内部技能 |
| **Adaptive Router (Rn)** | 检索相关记忆、选择能力并组装执行上下文 zn = Rn(in, Mn, Cn) | 路由提示、选择标准、工作流模板 |

### 2.3 受保护的装置演化流程

1. **Continual Optimizer（持续优化器）**：
   - 基于部署中的装置 Hn 和交互证据 en = (un, in, zn, yn, fn)，调用冻结的基础模型生成候选装置 Ĥn+1；
   - 当多个组件需要修改时，按预定义顺序逐一处理，每个组件生成最多 K 个备选方案，保持其他组件不变进行评估，只保留通过门控的最高分备选。

2. **Continual Evaluator（持续评估器）**：
   - **当前改进（Current Improvement）**：候选装置在当前任务验证集上的性能提升满足 Δn ≥ δn；
   - **历史保留（Historical Retention）**：候选装置在历史锚点集 An 上造成的历史损失 Dn ≤ Bn（Bn 为容忍度），其中 Dn 统计"在当前装置上成功但在候选装置上失败"的锚点数量；
   - **有效性（Validity）**：候选装置通过语法、输出模式、工具使用合法性、任务约束等检查；
   - **提交决策**：三项条件全部满足才允许提交（G=1），否则装置保持原状。多个候选通过门控时按复合分数排序，取最高者。

### 2.4 与传统持续学习的联系

论文指出 HCL 在概念上与模型中心持续学习的方法家族对应：Experience Memory 对应重放（replay）、Capability Map 对应表示学习（representation）、Adaptive Router 对应架构化方法（architecture）、Optimizer+Evaluator 对应优化与正则化方法（optimization/regularization），但将这些互补原则统一到单个协调演化的装置框架中。

## 6. 论文的主要结论与发现

1. **HCL 能有效积累能力并恢复失败**：在 Minecraft 中 HCL 完成全部 50 个任务，而 Static Harness 在 15 个任务后停滞；HCL 的环境动作数（83）少于 MemRL（88）和 MemP（91），执行效率更高。
2. **装置级遗忘真实存在且可测量**：受控保留扫描显示，随着历史损失容忍度 b 从 0 增至 ∞，平均遗忘从 0.39 升至 3.45，证明装置更新确实会破坏先前行为。
3. **稳定性—塑性权衡可显式调节**：仅改变 Bn 即可在保留与适应之间切换——Stability-HCL 在文本流上遗忘为 0.00，但最终平均性能较低（52.20%）；Plasticity-HCL 最终平均性能更高（64.70%），但遗忘有所增加（0.07）。
4. **更激进的更新不一定更好**：在 b 扫描中，最高的最终平均性能出现在 b=1（63.46%），而完全不受限制的 b=∞ 反而降到 60.13%，说明过度追求当前任务改进可能破坏后续演化所需的可复用装置内容。
5. **四个组件互补贡献**：完整 HCL 性能最高（多模态流 63.41%），禁用 Memory 或 Interface 更新造成的下降最大。
6. **与现有基线的对比优势**：在 ALFWorld 上，HCL 的最终平均成功率（61.74%–62.98%）超过所有基线；在多模态流上，HCL 最终平均（67.96%–68.92%）大幅超过 Zero-shot（39.40%）和 DGG（42.73%），相对提升超过 10%。

## 7. 优点

- **问题定义清晰且有新意**：首次系统性地将"模型外装置"作为持续学习的对象，提出"装置级遗忘"这一明确概念，拓展了持续学习的范式边界。
- **框架设计模块化且统一**：四个组件（接口、记忆、能力、路由）覆盖了智能体 harness 的核心执行功能，将候选生成与提交决策分离的"守卫式演化"设计简洁而有效。
- **历史保留的显式可控**：通过历史锚点集和容忍度参数 Bn，将稳定性—塑性权衡变成一个可调旋钮，而非隐式属性；这在持续学习文献中较为少见。
- **实验场景多样**：覆盖文本推理、多模态感知、开放世界交互三类代表性场景，且使用了多个不同规模和家族的冻结模型，增强了结论的泛化性。
- **消融与权衡分析完整**：组件消融和保留扫描相互补充，不仅验证了各组件的必要性，还揭示了"严格约束"与"过度自由"之间的非线性关系。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量、运行时长、总体成本，严重影响可复现性和实际部署评估。
